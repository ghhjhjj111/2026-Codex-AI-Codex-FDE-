Codex 行动营课程笔记：AI 工程交付十大核心技能清单
学完 Codex 行动营，我最大的感受是：AI 工程交付，不是会聊天、会生成、会调工具就够了。真正的分水岭，在于你能否把模糊需求变成可运行、可验收、可维护的交付物。Codex 这类工具能大幅提升效率，但它不会自动替你判断方向、控制风险、承担责任。下面这份十大核心技能清单，是我整理的课程笔记，也是 AI 工程交付路上必须跨过的关卡。

第一，需求翻译与任务拆解。 业务方说“做个智能助手”，这不是需求，只是愿望。工程交付第一步，是把愿望翻译成可执行任务：谁用、什么场景、输入输出是什么、成功标准是什么、错误代价有多大。任务拆得越清楚，AI 越能帮上忙；需求越模糊，生成结果越像废话。

第二，上下文工程。 AI 的产出质量，很大程度取决于你给它什么背景。相关文档、业务规则、参考范例、约束条件、历史决策，都要有选择地提供。上下文不是越多越好，噪音会干扰判断。学会筛选、分层、摘要和更新，是工程交付的基本功。

第三，规格与提示设计。 提示不是咒语，而是规格说明。目标、角色、限制、格式、验收标准，都要写清楚。好的规格能减少反复试错，让 AI 输出更稳定。不要指望一句话解决复杂问题，要把大任务拆成小步骤，逐步确认。

第四，生成结果审查。 AI 会一本正经地犯错。工程交付者必须能读、能判断、能修改。关注逻辑是否自洽、边界是否覆盖、安全是否达标、性能是否可接受。不要因为“能跑”就放过，生产环境和演示环境是两回事。

第五，调试与故障定位。 报错不可怕，可怕的是不知道从哪查。最小复现、二分排查、日志追踪、假设验证，这些方法依然有效。AI 可以帮你分析，但不能替你建立排查思路。能快速定位问题，才是工程能力的体现。

第六，测试与评测。 没有评测，就没有迭代。功能测试、边界测试、回归测试，一个都不能少。AI 应用还要做效果评测：准确率、召回率、延迟、成本、用户满意度。离线看基线，在线看反馈，人工抽检看边界。评测标准越清晰，交付质量越可控。

第七，版本控制与协作。 AI 生成的内容也要可追溯。分支管理、提交记录、代码评审、回滚机制，都是团队协作的基础。不要把所有改动堆在一起，否则出了问题无法定位。版本控制不是形式，而是安全网。

第八，集成与部署。 把生成物接入真实系统，才是交付的开始。接口是否匹配、配置是否正确、权限是否清晰、环境差异是否处理、能否灰度发布，这些都决定项目能不能上线。只会做 Demo，不算工程交付。

第九，成本与性能优化。 模型调用不是免费的。模型选择、缓存策略、批处理、并发控制、限流降级，都会影响成本和体验。能省、能快、能稳，才是成熟的工程方案。优化不是抠门，而是对业务负责。

第十，安全合规与责任。 数据隐私、权限最小化、敏感操作确认、日志留痕、人工兜底，都是必答题。AI 能自动执行，也意味着可能自动犯错。关键环节必须有人负责，出了问题要能回滚、能解释、能改进。

最后还有一项贯穿始终的能力：复盘与文档。把项目中的决策、踩坑、优化记录下来，形成可复用的资产。工具会变，模型会变，但这十项技能不会过时。Codex 行动营的价值，不是教你依赖某个工具，而是帮你建立一套从需求到交付的完整框架。能持续交付，才是真正的竞争力。
